## 板块 A：运算符与括号

### Q1（10.25）`[]` 和 `()` 有什么区别？

**答**：

- `[]` 方括号 = **取值运算符**：用来取列表的下标、字典的键值。
- `()` 圆括号 = **函数调用**：写在函数名后面表示"执行这个函数"。

在 dict 场景下：

| 写法 | 本质 | 在 dict 上的行为 |
|---|---|---|
| `data["city"]` | 方括号取值（运算符） | 键存在→取键值；键不存在→**KeyError 崩** |
| `data.get("city", "未知")` | 圆括号调用 `.get()` 函数 | 键存在→取键值；键不存在→**返回默认值，不崩** |

**做题口诀**：

- 键一定存在 → 用 `变量["键"]`（快、简洁）
- 键不确定 → 用 `变量.get("键", 默认值)`（不崩）

**顺带提醒**（新手常混）：`( )` 在代码行里还能是元组或普通分组，比如 `(1, 2)` 是 tuple；但写在函数名后面就是调用。判断标准：前面是函数名/方法名 → 调用；前面不是 → 可能是分组或元组。

## 板块 B：字典取值与防崩

### Q2（10.26）嵌套字典怎么取值？查不确定的键怎么写？

**答**：

- **嵌套取值**：`a["outer"]["inner"]` 表示先取 `a` 中键 `"outer"` 的值，再从结果中取 `"inner"`。中间任何一层键不存在，会直接 `KeyError` 崩。
- **防崩写法**：`a.get("outer", {}).get("inner", "默认")`。
  - 第一层 `.get("outer", {})`：键不存在时返回 `{}`（空字典）而不是 `None`
  - 第二层再对空字典 `.get("inner", "默认")`，取不到就给默认值

**默认值类型要对**：

- 默认返回 0 → 写 `data.get("age", 0)`（int）

### Q3（10.27）嵌套 `.get()` 的默认值为什么第一层是 `{}` 而不是 0？

**答**：

- 第一层默认值类型必须和"下一层要调的方法"匹配。下一层调 `.get()`（字典方法）→ 第一层默认就得给字典 `{}`；下一层取 `[]`（列表下标）→ 第一层默认就得给列表 `[]`。
- 如果把第一层默认值写成 `0`（整数）：user 不在 → 第一层返回 0 → 然后 `0.get("age", 0)` 崩（int 没有 .get() 方法，报 AttributeError）。
- **口诀**：每层默认值的类型 = 下一层要操作它时需要的类型。最后一层默认值才是真实业务值（0 / -1 / "未知"）。

### Q4（10.27）`.get()` 的默认值什么时候用 0，什么时候用 -1（哨兵值）？

**答**：

- **0 是合法真实值 / 下游会特判 0**（年龄 0 岁、点赞 0 次、`if x == 0` 特殊处理）→ 缺失得用哨兵值（-1 / None），否则"缺失"被当"真实 0"。
- **0 本身只代表"没有"**（0 次、无标记位，下游不特判）→ 默认 0 就够。
- **判断 2 问**：① 0 在业务里是合法真实值吗？② 下游代码会不会拿 `== 0` 做特殊判断？两问有任一"是" → 用哨兵值 -1。
- **写法**：嵌套 `.get()` 里把默认值位置的数直接替换（`get("age", -1)`），不用拼接或 int() 转。

### Q5（10.27）嵌套 `.get()` 取不到时，最终一定返回默认值吗？为什么？

**答**：

- 只要"某层键取不到"，那层就落到它的默认值。最终返回值 = **最内层取不到时给的默认值**。
- `safe_age({})` 执行：① user 不在 → 第一层给 `{}`（兜底容器）；② 在 `{}` 里取 age → 取不到 → 第二层给默认值 0。最终返回 **0**。
- **关键**：0 永远来自"取不到 age 的那一层"的默认值，不管第一层是真实取到还是默认兜底。
- 3 种场景对比：`{"user":{"age":30}}`→30（真实）；`{"user":{}}`→0（user 在但 age 不在）；`{}`→0（user 不在，第一层兜底 {}）。后两种都返回 0，但路径不同。
- 默认返回 `"未知"` → 写 `data.get("city", "未知")`（str）
- 默认值类型和后续操作要匹配，否则又掉进"引号决定类型"的坑（错题库 ⑪⑫⑬⑭ 根因）

## 板块 D：解释器与终端（PowerShell vs Python REPL vs 跑脚本）

### Q1（10.26）为什么在 PowerShell 里敲 `print(double(5))` 报 `CommandNotFoundException`？

**答**：

- **PowerShell 提示符 `PS D:\...>`**：Windows 自带命令终端，只认系统命令（cmdlet、exe、脚本文件）。它把 `double` 当成"要执行的命令名"去找，找不到就报 `CommandNotFoundException`。
- **Python 解释器提示符 `>>>`**：只有在这个提示符下，`print`、`double`、`count_chars` 才是 Python 能认的语法。
- **跨终端调 Python 函数**：两条路：
  1. **进交互模式 + import**：PowerShell 里敲 `python` 进 `>>>`，再 `from day05_function import double`，然后调
  2. **直接跑脚本**（推荐）：PowerShell 里敲 `python day05_function.py`，脚本里所有 `print` 语句从上到下执行

**做题口诀**：

- 看到 `PS D:\...>` 提示符 = 在 PowerShell，只能敲系统命令
- 看到 `>>>` 提示符 = 在 Python 解释器，能调 Python 函数
- 想调脚本里定义的函数，**要么 import 要么跑脚本**，直接在 PowerShell 里敲函数名 100% 报错

**踩坑点**：

- PowerShell 把 `print`、`double` 等当成命令名找，找不到就 `CommandNotFoundException`
- 脚本里的 `def` 定义的函数**只在脚本内有效**，外部要 import 才能用
- 改脚本时把注释掉的 `print` 取消注释（去掉行首 `#`），再 `python 文件名.py` 跑

## 板块 E：return vs print（10.27 新增）

### Q1（10.27）`add(5)` 单独一行为什么屏幕上没输出？

**答**：

- `add(5)` 里用的是 `return a + b`，**return 把值交出去但不打印**。单独一行 `add(5)`，值（5）交出去了，没人接、没人 print，屏幕上一个字都没有。
- 想看到结果，得写 `print(add(5))`（return 交出的值套一层 print）。

**`return` 和 `print` 4 个区别**：

| 对比项 | `return` | `print` |
|---|---|---|
| 作用 | 把值交回给调用者 | 把值显示到屏幕 |
| 屏幕上能看到 | ❌ 看不到（除非外面套 print） | ✅ 直接显示 |
| 函数后续代码 | return 后**立刻停止执行** | print 后**继续执行** |
| 返回值 | 函数的"出口值" | 函数没有 return 时默认返回 None |

**做题口诀**：
- 想"看到" → `print(x)`
- 想"把 x 交给别人用" → `return x`
- 想"既看到又交给别人用" → `return x`，调用处写 `print(func(参数))`
